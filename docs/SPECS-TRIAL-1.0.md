## 4. المهام (Definition of Done)

### المهمة 0: نموذج التسجيل الفعلي

**يحل محل:** النسخ/الطباعة اليدوي من `landing/index.html`

**Migration (Supabase CLI):**
```sql
create table trial_signups (
  id uuid primary key default gen_random_uuid(),
  company_name text not null,
  work_email text not null unique,
  country text,
  headcount_estimate integer,
  file_format text, -- CSV / XLSX
  interest text, -- JSON array: [التذكيرات, التقارير, دعم العربية, السعر]
  source_landing text, -- /en أم /ar
  honeypot text, -- خفي
  created_at timestamp default now()
);

-- RLS: إدراج عام للمجهول (anon INSERT فقط)
-- لا SELECT لأحد سوى service_role
```

**الحقول:**
- اسم الشركة (نص)
- البريد العملي (فريد، قيد تكراري)
- الدولة (اختياري)
- حجم العمالة (تقدير)
- صيغة الملف (CSV / XLSX)
- أهم ما يهمك (قائمة متعددة: التذكيرات / التقارير للمراجعات / دعم العربية / السعر)
- honeypot (خفي من المستخدم)

**الحماية:**
- honeypot: حقل مخفي (CSS `display: none`) — إذا ملأه بوت، ترفضه الخادمة
- فحص النطاق: رفض gmail/hotmail/outlook بتحذير (لا مانع صارم — الشركات الصغيرة تستخدمها)
- قيد فريد على `work_email`: تثبيت التسجيل المكرر

**الإرسال:**
- من `/en` و `/ar` معاً
- بعد الإرسال: رسالة تأكيد «سنوافيك ببيانات دخولك خلال يوم عمل واحد»
- زر واتساب `wa.me` برسالة جاهزة للمتابعة الفورية

**الاحتياط:** النموذج القديم (نسخ/طبع) يبقى بـ feature toggle، افتراضه الجديد (form عصري)

**✅ تعريف الإنجاز:**
- إرسال من `/en` و `/ar` يسجل صفاً في Supabase خلال دقيقة
- إدخال مكرر بالبريد نفسه يُثبَّت (لا تكرار)
- honeypot لا يظهر للمستخدم
- الاختبارات الحالية كلها خضراء (لا كسر للصفحة)

### المهمة 1: إنشاء الحساب التجريبي — يدوي في v1.0

**Runbook يدوي:** المالك يستلم إشعار (فحص جدول `trial_signups` يومياً)

**الخطوات:**
1. لوحة Supabase → Authentication → Add user
2. البريد العملي من `trial_signups`
3. كلمة مرور مؤقتة + Auto Confirm OFF
4. تأكيد يدوي أو Magic Link يدوي
5. جدول `workspaces`: صف جديد (اسم الشركة) + `trial_ends_at = اليوم + 7 أيام`
6. جدول `workspace_members`: صف جديد (المستخدم بدور owner)
7. إرسال بيانات الدخول عبر واتساب/البريد (نص من المهمة 4)

**حد أقصى:** 20 حساباً تجريبياً ثم قائمة انتظار (قرار مرجعي)

**✅ تعريف الإنجاز:**
- أول عميل حقيقي دخل ورفع ملفاً خلال 48 ساعة من الإنشاء
- مساحته معزولة (لا يرى غيرها)
- تجربته تنتهي بعد 7 أيام تقويمية (توقيت `Asia/Riyadh`)

## 8. سجل التعديلات

**v1.2 — 2026-10-24 (مساءً)**  
ثلاثة تصحيحات اعتمدها المرجع بعد تحقق مباشر من المستودع، بطلب من المنفذ:  
1. **جدول workspaces:** لا يحمل `trial_ends_at` ولا `subscription_tier` — العمود الوحيد `plan_tier`. أُضيف بند Migration في المهمة 2 يضيف `trial_ends_at timestamptz` مع قاعدة NULL = «ليس تجريبياً» لحماية مساحة المالك.  
2. **استعلام إشارة الشراء:** النموذج يخزن الاهتمامات بمفاتيح إنجليزية في jsonb (`reminders`/`reports`/`arabic`/`pricing`) — صُحح الاستعلام إلى `interest @> '["reminders"]' or interest @> '["pricing"]'`.  
3. **استعلام النشاط اليومي:** `auth.users` لا يحمل `workspace_id` — صُحح بالربط عبر `workspace_members`.  
كما عُرّفت نافذة العدّ رسمياً: **2026-10-24 → 2026-11-07** (من نشر النموذج على الموقع الحي)، مع حق المالك إرجاع البداية مرة واحدة لتاريخ أول مشاركة فعلية.

**يحل محل:** النسخ/الطباعة اليدوي من `landing/index.html`

**Migration (Supabase CLI):**
```sql
create table trial_signups (
  id uuid primary key default gen_random_uuid(),
  company_name text not null,
  work_email text not null unique,
  country text,
  headcount_estimate integer,
  file_format text, -- CSV / XLSX
  interest text, -- JSON array: [التذكيرات, التقارير, دعم العربية, السعر]
  source_landing text, -- /en أم /ar
  honeypot text, -- خفي
  created_at timestamp default now()
);

-- RLS: إدراج عام للمجهول (anon INSERT فقط)
-- لا SELECT لأحد سوى service_role
```

**الحقول:**
- اسم الشركة (نص)
- البريد العملي (فريد، قيد تكراري)
- الدولة (اختياري)
- حجم العمالة (تقدير)
- صيغة الملف (CSV / XLSX)
- أهم ما يهمك (قائمة متعددة: التذكيرات / التقارير للمراجعات / دعم العربية / السعر)
- honeypot (خفي من المستخدم)

**الحماية:**

- فحص النطاق: رفض gmail/hotmail/outlook بتحذير (لا مانع صارم — الشركات الصغيرة تستخدمها)
- قيد فريد على `work_email`: تثبيت التسجيل المكرر

**الإرسال:**
- من `/en` و `/ar` معاً
- بعد الإرسال: رسالة تأكيد «سنوافيك ببيانات دخولك خلال يوم عمل واحد»

**الاحتياط:** النموذج القديم (نسخ/طبع) يبقى بـ feature toggle، افتراضه الجديد (form عصري)

**✅ تعريف الإنجاز:**
- إرسال من `/en` و `/ar` يسجل صفاً في Supabase خلال دقيقة
- إدخال مكرر بالبريد نفسه يُثبَّت (لا تكرار)
- honeypot لا يظهر للمستخدم

### المهمة 1: إنشاء الحساب التجريبي — فوري ذاتي (حوّلها المالك 2026-10-25)

**التصميم المعتمد:** نموذج `/trial` يطلب كلمة مرور من العميل (حد أدنى 8 أحرف)، ثم Edge Function بمفتاح الخدمة تنفذ الذرّة كاملة. يحل هذا محل الإنشاء اليدوي، ويبقى الـrunbook اليدوي احتياطاً للحالات الخاصة.

**التدفق:**
1. النموذج يرسل الصف إلى `trial_signups` كما هو اليوم (anon insert)، ويستلم `id` الصف (‎`Prefer: return=representation`‎ — لا يحتاج SELECT).
2. النموذج يستدعي Edge Function ‏`trial-provision` بتمرير: معرّف الصف + كلمة المرور.
3. الدالة بمفتاح الخدمة: تقرأ الصف بالمعرّف ← تتحقق أن honeypot فارغ ← تتحقق السقف (عدد المساحات التي `trial_ends_at` ليس NULL فيها < 20) ← تنشئ المستخدم بـ admin API ‏(email_confirm=true، بلا رسالة بريد) ← تنشئ المساحة ‏(`trial_ends_at` = منتصف ليل الرياض بعد 7 أيام بالضبط) ← العضوية owner ← تحدث الصف (‎status='active'‎ + user_id + workspace_id).
4. العميل يسجّل الدخول مباشرة ببياناته إلى `/app`.

**التسابق المزدوج عند السقف:** مقبول (21 بدل 20 لا يكسر شيئاً) — لا حاجة لقفل استشاري في هذه المرحلة.

**إخفاق أي خطوة:** رسالة عامة للعميل + الصف يبقى `pending` ويُحاول مرة أخرى أو تدخّل يدوي. البريد المكرر في auth.users ← رسالة «هذا البريد مسجل — جرّب الدخول».

**بعد السقف (20):** الدالة لا تنشئ شيئاً؛ تحدث الصف ‏status='waitlisted' ويعرض النموذج رسالة قائمة الانتظار.

**الحمايات الإلزامية (خادمية، لأن الدالة قابلة للاستدعاء المباشر بعيداً عن النموذج):**
- honeypot فارغ (فحص خادمي للصف)
- تحقق طول/صيغة كل الحقول كقيود الجدول نفسها
- السقف + فريدية البريد
- كل محاولة إنشاء تُسجَّل (الصف موجود أصلاً — بما فيه المحاولات الفاشلة عند الإبقاء على status='pending')

**المقايضة المعتمدة:** البريد غير مُتحقَّق منه حتى شراء النطاق وتفعيل Resend — يقبلها المالك. **العلاج بعد النطاق (يسجَّل كالتزام للمرحلة 2):** تفعيل تأكيد البريد + إجراء «تحقق بريد» شرط للتحويل إلى خطة مدفوعة، ومنع التسجيل ببريد غير مُتحقق منه في حسابات جديدة بعدها.

**الـmigration المطلوبة (بصيغة CLI، في نفس PR):**
- `workspaces`: إضافة `trial_ends_at timestamptz` (NULL = ليس تجريبياً — نفس قاعدة المهمة 2)
- `trial_signups`: إضافة `status text not null default 'pending' check (status in ('pending','active','waitlisted'))` + `user_id uuid references auth.users(id)` + `workspace_id uuid references workspaces(id)`
- تسجيل الدالة في `supabase/config.toml` — لا أسرار في الكود؛ مفتاح الخدمة في متغيرات بيئة Supabase فقط

**✅ تعريف الإنجاز:**
- عميل جديد يسجّل من `/trial` بالعربي والإنجليزي ويدخل `/app` بمساحته خلال دقيقة بلا أي تدخل يدوي
- السقف: المساحة رقم 21 تُرفض برسالة قائمة انتظار وstatus='waitlisted'
- المساحة رقم 1 (مساحة المالك، trial_ends_at = NULL) لا تتأثر بأي شرط من شروط التجربة
- العزل: المستخدم الجديد لا يرى إلا مساحته (اختبار على مستوى القاعدة)
- الاختبارات كلها خضراء + اختبارات جديدة للدالة (النجاح، البريد المكرر، honeypot المملوء، السقف)

ثلاثة تصحيحات اعتمدها المرجع بعد تحقق مباشر من المستودع، بطلب من المنفذ:  
1. **جدول workspaces:** لا يحمل `trial_ends_at` ولا `subscription_tier` — العمود الوحيد `plan_tier`. أُضيف بند Migration في المهمة 2 يضيف `trial_ends_at timestamptz` مع قاعدة NULL = «ليس تجريبياً» لحماية مساحة المالك.

كما عُرّفت نافذة العدّ رسمياً: **2026-10-24 → 2026-11-07** (من نشر النموذج على الموقع الحي)، مع حق المالك إرجاع البداية مرة واحدة لتاريخ أول مشاركة فعلية.
